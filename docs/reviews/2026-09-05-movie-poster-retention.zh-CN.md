# 电影海报本地缓存与定期清理

大陆票房页面曾在 2026-09-05 19:56 PDT 生成 1 张真实海报和 4 张占位图；海报下载与票房抓取共用 20 秒预算，且缺图后只能等常规 6 小时 DATA 刷新。成功状态只反映票房数据来源，不能证明海报完整。

本次将电影海报保存在独立的持久目录 `INKYPI_DATA_DIR/plugins/<plugin id>/posters`。大陆和北美电影插件分别管理，避免通用临时缓存的全局驱逐影响已下载的海报。既有海报按精确 URL 对应的旧文件迁移，沿用官方影片身份及标题/年份校验。

保留规则：

- 每个插件最多 256 张、32 MiB；单张 JPEG 最多 2 MiB，尺寸限制为 600×900 以内。
- 使用时更新访问时间，最多每天写一次时间戳，减少 SD 写入。
- 常规生成时检查清理；30 天未使用的图片可清除，超出容量或数量时先清除最久未使用的非当前封面。
- 当前榜单使用的封面受保护；若被保护文件已占满预算，则拒绝新增，保留现有文件。
- 写入采用同目录临时文件和原子替换；清理只处理受管的 URL 哈希 JPG，拒绝根目录及父目录符号链接。
- 更新访问时间、旧图迁移或清理失败不会隐藏已验证可读的封面或阻断正常榜单渲染。

大陆缺图补全借用已有后台 LIVE 通道和资源准入机制，首次等待 5 分钟，连续不足时退避到 10、20、30 分钟，补齐后停止。后台补图不强制切换显示，不改 DATA 周期，不提升票房数据源的时间。任务执行时再次校验来源缓存的身份、有效期与北京时间日期，过期即取消，等待 DATA 通道。图片元数据和日志单独记录海报就绪数量。

验收使用既有插件生成、后台调度和缓存存储接口，覆盖缓存迁移及无网络复用、数据时间保持、慢网分批补图、容量/数量淘汰、当前图保护、只读读取、维护失败、任务排队后过期，以及目录链接边界。Windows 未授权符号链接创建的用例在当地跳过，由 Linux CI 执行。

这份文件说明实现与验收范围；实机部署、源哈希、终态任务、完整画面与复用结果另保存在本次本地验收证据中。通用缓存此前具体删除了哪些海报缺少逐文件证据，因此不把原始缺图事件归因于某一次确定的清理。
