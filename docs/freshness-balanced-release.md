# 轮播稳定与内容时效：实现及发布验收

基线：`db735ab30e1642f42b209274e2654becf39314f9`。工作分支：`codex/freshness-balanced-20260902`。本轮只组合调度、展示、资源、票房四项修改，没有重放已回滚的大改动。线上部署和实例配置迁移需要另行授权。

## 四个审查单元

1. **调度**：首次 DATA 等待起点保存在调度器内存，以实例 UUID、结构版本和设置版本区分。排序及饥饿保护使用同一等待年龄；失败、退避和资源延期保留年龄；成功、删除、停用、取消 interval、版本变化清理。重启重新建立起点，不改变持久化格式。
2. **展示**：内部轮播候选加入当前请求的 prepared 图片。候选选择和执行分别校验请求、配置身份、主题和文件；实际写屏提交后才推进 receipt、last-good 和已读状态。失效 prepared 只清理匹配请求的准备标记，保留请求进入现有有限退避，并允许其他实例轮播。
3. **资源**：漫画和历史图片首次选择仍完整校验；已有 pending selection 时只读取选定图片，重试沿用内容。准备日志记录总耗时、请求等待年龄、前后 RSS 和进程 HWM；HWM 是进程生命周期峰值，不是单次任务独占峰值。保留 HARD 保护、重任务串行和写屏预算，不调整全局并发或内存阈值。
4. **票房**：新增 `official_china`，从[中国电影票房实时页](https://zgdypf.zgdypw.cn/box)读取有效结构化数据。保存北京时间统计日、源更新时间、抓取时间和“综合票房、含服务费”口径。有效数据后才使用剩余预算补全标题/海报。旧缓存缺少源时间时显示“时间未知”，过期回退仍不计 DATA 成功。

## 票房边界

- 所有官方数据和可选网络获取共用最多 20 秒预算，并受调用方更早截止时间限制。可终止子进程覆盖 DNS/读取阻塞；启动、准入、读取及回收都计入预算，并预留清理时间。
- 使用现有全局 HEAVY_CHILD / provider-exclusive 许可；不会新增全局并发槽。单次网络客户端关闭内部重试，共享预算层最多重试一次暂时性故障；403 不立即重试。
- 保留原猫眼模式。当前可用猫眼结构没有已验证的同口径源时间，因此官方模式不会将猫眼数据伪装成官方实时数据；只有将来取得可验证的同口径数据，才可接入该备用路径。
- 官方源空列表、缺少综合指标、无有效源时间或跨北京时间统计日均拒绝发布。失败不重写旧缓存的内容、生成时间、源时间或文件 mtime。
- 切换官方模式后的首次请求失败时，只允许“其他配置完全一致、仅旧大陆 sourceMode 不同”的缓存降级回退，并核对每行来源、来源标签和原生成时间。不会跨用北美缓存，也不会给旧数据补造官方口径或源时间；主题专用渲染仍要求当前配置精确匹配。
- HTTP 清理只有一次；进程句柄关闭与 shutdown 的 join 共用终止锁，避免 Windows 竞态。日志记录单次 GET 总耗时、剩余预算及终态，不输出响应正文或认证信息。
- 没有新增公共 HTTP 接口。北美插件 `china_box_office_top_movies` 不迁移。

## 本地验证

使用既有 Python 3.11.9 应用环境及原生 Pillow，未调整依赖适配其他解释器。

- 全量回归：5953 通过，48 跳过；超时兜底修复后，HTTP、子进程执行器、源校验和资源契约相关 75 项通过；迁移首刷回退补齐后，票房、配置迁移、HTTP 和资源契约相关 101 项通过。发布前另执行最终提交的干净归档验证，结果与归档 SHA-256 保存在发布包旁的验证记录。
- 六个无 DATA 成功记录实例的混合负载、公平等待跨失败/退避、重启、配置变化均有回归。
- prepared 回归覆盖“夜间正式缓存 + 白天 prepared + 正常其他插件”、缺失/损坏/过期文件、写屏失败、主题变化；已有取消和提交失败回归继续通过。
- 重复解码计数：漫画首次 10 次、pending 重试 1 次；历史图片首次 25 次、pending 重试 1 次。两者重试输出像素完全一致。
- 28 实例采用当时线上真实刷新周期，分别运行健康负载及 HARD/SOFT 压力、首次提供方失败的 24 小时虚拟时间测试。每组 287 次模拟自然写屏，间隔 300–310 秒；六个空 DATA 实例首次执行全部在一小时内（健康组最晚 1000 秒，压力组最晚 2460 秒），28 个实例均取得 DATA 成功并满足持续等待上界。
- 模拟使用真实调度/队列/提交流程和模拟提供方、20 秒渲染及 60 秒硬件写入。该长测隔离 DATA/轮播，prepared 生命周期由独立回归证明；不等同于设备上的真实提供方长稳、物理屏幕或 OOM 验收。
- 实际官方路径在本机完成抓取及 800×480 渲染，耗时约 1.9 秒；检查了来源时间、统计日期和图像。海报无凭据时使用现有占位图，不影响有效票房数据。

## 授权后的部署与实例迁移

1. 重新读取设备活动版本、28 实例清单及运行状态，确认仍以预期线上基线运行；记录六个空 DATA 实例及原 prepared 请求身份。基线或设置变化时先核对差异。
2. 使用同一最终提交的 tracked-only ZIP。部署从主工作区的 `tools/epaperpod-deploy-zip.ps1` 发起，复用已固定的 SSH 身份和主机密钥。核对归档 SHA-256、活动版本和 previous 回滚指针。
3. 精确迁移大陆票房实例。`src/china_source_migration.py` 只生成离线候选：输入配置快照、SHA-256、目标 UUID、结构版本及设置版本必须匹配。它只改变目标 `sourceMode`、递增版本并加入幂等迁移标记；不自动写线上配置。
4. 在授权维护窗口内停止配置写入方，重新获取配置快照并生成候选。应用前再次核对快照 SHA-256，以现有配置存储的原子写入方式保存并保留原文件/权限；随后启动服务。配置已经变化则重新生成，不能覆盖较新的运行状态。迁移工具本身不负责停服、安装或替换线上文件。
5. 同时保留部署前代码版本及配置备份。若触发回滚，恢复对应代码和配置；不删除内容缓存和 prepared 证据。

离线候选命令（参数来自当次捕获，不能照抄占位值）：

```text
python src/china_source_migration.py --input captured-device.json --output candidate-device.json --expected-sha256 CAPTURE_SHA256 --instance-uuid TARGET_UUID --generation GENERATION --revision SETTINGS_REVISION
```

## 现场验收：至少两轮完整自然轮播，约五小时

28 实例按每项约五分钟估算，一轮约 140 分钟，两轮约 280 分钟；以真实轮播完成情况为准。此处“两轮”不是两次写屏。

- 六个此前无 DATA 成功记录的实例均取得首次执行机会，分别记录请求、开始/结束时间及结果；外部故障应与调度饥饿分开归因。
- 原 prepared 请求在身份和主题仍有效时完成实际写屏、对应 receipt/last-good/已读提交。主题或配置变化使原请求失效时记录取消原因并验证替代请求，不能误报原请求成功。
- 从带来源的自然 Waveshare 写屏日志计算间隔，通常约五分钟；手工刷新、缓存生成和健康检查不能代替自然轮播证据。
- 官方票房取得有效当前北京时间数据，源时间正确；无法取得同口径数据时保留旧数据及旧时间，DATA 记录维持失败/降级。
- 检查服务退出及重启、内核/earlyoom、进程 RSS/HWM、可用内存及 swap、准备耗时和等待原因。任何 OOM 或异常重启均不能算通过。
- 核对提交后的当前图像、manifest、源/缓存时间和真实硬件写入。光学显示效果仍需设备照片或现场观察，不能由驱动日志推断。

最终验收记录包含最终代码 SHA、归档 SHA-256、配置迁移身份、观察起止时间、自然写屏间隔、六实例进度、prepared 回执和异常清单。
